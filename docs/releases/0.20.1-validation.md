# 0.20.1 发版验证

版本 0.20.1，构建号 38。针对 0.20.0 在 fnm 环境下无法读取 DSH 本机会话的问题。

## 复现与原因

正式应用显示“等待连接”和“读取 Harness 数据需要 Node.js”。本机 DSH Web / TUI 的进程使用 fnm 下的 Node 24.14.1；应用环境的 PATH 中没有 Node，两个固定系统安装位置也不存在。原定位器未识别版本管理器目录，导致 Zstandard 会话日志无法解码。客户端运行与本地读取是否成功是两回事。

## 修复验证

- `check-node-locator.sh`：隔离目录覆盖精简 PATH、fnm 默认别名、数字版本排序、不可执行文件、macOS 含空格目录、自定义 FNM_DIR、nvm 和 Volta；保留显式 PATH 的优先级。
- `check-local-agents.sh`：原会话状态、Token、重复读取、进程识别与本机交互回归通过。
- 在 `env -i` 中仅保留正常 HOME 和 `/usr/bin:/bin:/usr/sbin:/sbin`，运行 `LocalAgentChecks --probe-dsh-health`：通过 fnm 默认别名找到 Node，成功解码本机 15 个 DSH 会话，没有读取错误。没有调用模型或提交回答。
- 通过桌面应用入口启动 Preview：DSH 状态从错误恢复为“未检测到工作”，随后观察到真实会话完成事件。空闲 Web/TUI 不等于有任务正在执行。
- `check-desktop-pet.sh --no-capture`：新增 DSH 读取异常文案断言，原自由猫状态与布局回归通过。
- `check-agent-data.sh`、`check-agent-interactions.sh`、`check-desktop-dock.sh --no-capture`、`check-agent-ui.sh --no-capture`、`check.sh` 均通过。

原生无捕获检查不作为截图验收；未更改 DSH 配置、API Key 或系统 PATH，没有重启 DSH。

## 发布验收

- Apple Silicon 与 Intel 构建、ZIP 解压与 DMG 只读挂载校验通过；主程序与两个助手架构一致，严格签名检查通过。
- 两份更新清单的版本为 0.20.1 / 38，归档 URL、大小、SHA256 与本地包一致，Ed25519 签名验证通过。
- 隔离 Sparkle 测试的取消、当前版本、损坏清单、损坏归档、完整安装均通过；安装后内容逐字节一致并成功重新启动。测试前后原安装应用的 Info.plist 和主程序 SHA256 未改变。
- GitHub 七个远端资源的大小与 SHA256 全部匹配后公开为 Latest；匿名下载两份更新清单与 SHA256 清单均与本地相同，签名校验通过。
- 随后通过本机正式应用的“检查更新”从 0.20.0 升级到 0.20.1，并执行安装与重新启动。安装后的 Info.plist、主程序与发布构建逐字节相同，严格签名检查通过。
- 更新后正式应用的 DSH 状态不再显示“等待连接”，显示本机会话用量，并观察到真实会话的完成时间；原来的 Codex、Claude Code、DSH 关注列表保留。DSH Web / TUI 未重启。

验证日志保存在本机 `.build/node-hotfix/`，不包含在发布包中。Intel 仅交叉编译和归档检查，未完成 Intel 真机验收。
