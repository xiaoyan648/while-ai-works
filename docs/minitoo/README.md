# MiniToo 展示与语音伙伴

本地开发功能：设置顶部与「桌面游戏」并列的独立「MiniToo」页面提供启用开关和「鱼缸 / Codex / 工作模式 / 闲聊模式」手动选择，独立于「开始玩」、跟随 AI、当前玩法。可从菜单栏的「MiniToo 展示」直接进入。页面切换不会改变桌面玩法或设备开关；鱼缸仍共用「水下观赏」的入住列表。不做自动切换，也不在任务完成时跳转模式。首次启用需要允许 macOS 蓝牙访问，设备需事先在 Mac 蓝牙设置中配对，名称为 `Divoom MiniToo-Audio`。

## 工作模式与闲聊模式

- **工作模式**：目标是 MiniToo 收音 → Mac 语音识别 → 自己的 Agent → 流式语音合成 → MiniToo 播放。角色跟随真实的聆听、思考和播放状态。
- **闲聊模式**：已接入火山豆包端到端实时语音，与工作模式分别手动选择。进入模式时只上传一张固定角色画面；聆听、思考、说话、打断及结束不再换图。聊天期间暂停画面上传，Mac 预览也保持静止。若正在发送画面，完成后才可开始闲聊。
- **当前已接入火山引擎文字 Agent。** 在「工作模式 → 打开 Agent 工作台」配置自己的 Key 和模型，可查询状态、控制展示与桌面开关，并选择允许打开应用和网页。工作角色跟随任务状态变化；收音、转写和流式播报需另配豆包语音 Key，实际验证结果与待验收范围分别记录。[配置、能力和验证说明](agent.md)
- 折叠区中的待机、聆听、思考、说话、完成仍是手动动作预览，不会打开麦克风或执行任务；任务进行时禁用预览切换。
- 角色采用浅色背景、黑色圆润身体和白色眼睛，加入眨眼、侧头、弹跳、伸缩和轻量状态符号。由 CoreGraphics 原生绘制，独立于模型供应商。
- 工作模式每个动作 16 帧 × 120 ms，循环周期 1.92 秒。预览复用缓存帧，上传后的动画由设备播放；仅切换动作时上传，短时间多次切换只发送最新待处理动作。工作模式动画不依赖 Codex 日志状态；闲聊使用单帧画面。
- 本地编码实测：待机 42,007 字节，聆听 48,906，思考 49,225，说话 49,019，完成 50,581。协议检查已验证全部 JPEG 可解码、尺寸 160 × 128、真实帧变化和完整动画容器；这些是编码大小，不代表蓝牙传输耗时。
- 2026-09-21 最初角色预览测试曾遇到设备接收请求超时；后续 Agent 联调中，应用已显示工作角色「设备已接收」。这是完整 ACK 的软件证据，设备画面观感仍需目视验收。
- 已加入麦克风权限、独立音频设备选择、豆包语音识别和流式合成。录音与播放分开，录音仅在内存中暂存。云端接口、设备与应用联调的历次结果见下方文档；实时语音启动恢复已做本地检查，MiniToo 双向连续通话仍需真机验收。[语音配置与验证](voice.md)

## 鱼缸

共用 `aquarium.residents` 入住列表（最多六种鱼）及图鉴中的鱼种 PNG，按真实选择显示鱼的外形和颜色。放入、移出、替换鱼时重新上传；空鱼缸显示“等待小鱼入住”。小屏是二维表现，游动轨迹独立于桌面三维场景，不逐帧镜像。图片素材缺失会在设置中提示。

游动周期约 9.6 秒，缩小移动范围，掉头时逐渐侧转，避免快速往返。

通过 Bluetooth Classic RFCOMM channel 1 上传 160 × 128、48 帧、每帧 200 ms 的鱼缸动画。发送一次后由设备循环播放，不持续抓屏、不调用云端服务，不需要 Python、Divoom 账号或额外守护进程。

## Codex

- 增量读取本机 Codex 会话日志，复用原有监控器；只保留生命周期和额度元数据，不保留提示词或回复内容。
- 页面显示运行中的会话总数，每页三条；在设置中手动翻页。编号在本次应用运行中稳定，重启后重新分配。
- 区分运行中、本轮完成、中断和状态未知。超过五分钟无事件标为未知，不能当作完成；有新活动可恢复。尾部日志缺失开始事件时不猜测运行时长。
- 运行时长以十秒为粒度更新；使用同一时间窗口内最新 Codex 额度快照，区分额度周期并显示更新时间。缺失显示不可用，额度已过重置时间显示待更新，不能推断额度已恢复。
- 本机日志不是云端实时额度查询；超过五分钟的额度快照标记“较早”。具体重置时间可在设置中查看。
- 不提供精确 token/s、云端其他机器会话或任务控制。
- 状态使用单帧 JPEG，每秒检查一次时间变化，日志文件事件经 100 ms 合并后触发采集，1.5 秒轮询作为兜底；画面没有变化则不重绘预览、不重发。页面完成后保持 Codex 模式。

所有内容共用一个串行蓝牙发送通道。当前上传完成后才发送最新选择，传输中的多次修改合并，不积压旧画面；设置预览是待发送内容，设备确认状态另行显示。传输失败后需要手动重试。

## 开关与连接

- 默认关闭；开关和显示模式保存在本机，重新打开应用时恢复。
- 关闭时取消尚未发送的动画包，在当前连接发送屏幕关闭命令；此设备固件执行熄屏但可能不回复，写入完成时提示“已发送熄屏指令”，不冒充收到设备确认。实际熄屏已由用户目视验证。
- 关闭的是屏幕，不是设备电源。重新开启会点亮屏幕并重新上传动画。
- 展示关闭时保留已建立的控制通道，避免反复重连导致 macOS 蓝牙控制通道不回应；退出应用时才释放它。
- 应用退出时释放自己的控制通道，不断开整个音频设备；设备可能继续播放已收到的动画。要熄屏，请先关闭展示开关。
- 蓝牙断开或传输超时后显示原因，可点「重试」；不会自动反复抢占手机连接。
- 首次亮屏后等待 0.5 秒再请求传输，已亮屏的连续更新跳过这一等待；数据包间隔 5 ms，失败后手动重试降为 20 ms。进度显示最多每秒更新十次。
- 首次请求无回复时，仅在尚未发送任何动画块的前提下重试一次请求。异步写入带序号，忽略重复或过期的完成回调。
- Mac 休眠时释放控制通道，唤醒后在开关仍开启时重新发送。
- 若 Mac 显示音频已连接但控制通道打不开，退出手机 Divoom App，必要时在 Mac 蓝牙设置中断开、重连设备后重试。

## 实现与检查

- `Sources/WhileAIWorks/MiniTooArtwork.swift`：共用鱼素材，CoreGraphics/CoreText 绘制，ImageIO 编码 JPEG，无第三方运行时。
- `MiniTooProtocol.swift`：包校验、增量解帧、动画容器、256 字节分块。
- `MiniTooAquarium.swift`：先用 CoreBluetooth 异步请求授权，再初始化 IOBluetooth；连接、写入和设备确认有独立状态和超时。只有收到请求才开始发块，只有收到完整动画 ACK 才显示已接收。
- `ContentView.swift`：手动模式、预览、开关、分页、进度、重试；独立设置页可滚动，进入 MiniToo 时收起钓鱼图鉴，返回桌面游戏时恢复。
- `Sources/WhileCore/CodexDisplay.swift`：会话状态和额度快照解析；`CodexMonitor.swift` 独立响应 MiniToo 的监控需求，不影响桌面游戏开关。
- `bash scripts/check-minitoo.sh`：协议固定向量、碎片与损坏数据、全部 JPEG 解码、分块重组、准备期间取消；会话恢复/中断/超时和额度空值/过期/顺序检查；输出本目录的 GIF/PNG 示例预览（示例鱼和额度，不是当前设备实拍）。
- `bash scripts/check-minitoo.sh --device`：显式真机测试，会发送动画；添加 `--off` 同时验证熄屏请求。日常开发检查不访问蓝牙设备。
- `bash scripts/check-hooks.sh`：原有多客户端监控回归，以及桌面和跟随关闭时的独立 MiniToo 监控。
- `bash scripts/check.sh`：原有玩法及原生设置渲染回归。
