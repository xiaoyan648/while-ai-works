# Claude 额度消失与查询间隔修复

本机测试版：0.20.4-beta.1 / 44。未发布正式版。

## 现象与原因

0.20.3 授权后曾成功读取真实额度，但后续请求返回 HTTP 403。系统 CFNetwork 日志证实请求收到 403；约 20 分钟暂停后的单次复查仍返回 403。Claude 桌面端仍显示自己的用量。不能仅凭 403 推断账号被判定为恶意或已经退出登录。

应用端有两个缺陷：窗口激活检测强制跳过共享缓存；桌面查询失败后，独立 CLI 的无订阅结果清除了桌面的成功额度。此外，界面使用本地会话报告时间显示“刚刚更新”，掩盖了真实额度的获取时间。

## 修复与验证

- 桌面读取统一使用随机 15～20 分钟的等待时间；失败后从 30～45 分钟退避，连续失败逐步扩大到 60～90、120～180 分钟。
- 手动刷新至少间隔 5 分钟，不能绕过失败等待；窗口激活不再强制跳过缓存。桌面读数和冷却期限持久化，不保存凭据。
- 保留临时失败前的成功额度及原始观测时间，标为上次读数。独立 CLI 的空额度不会覆盖它；账号、组织变化或退出登录时清除旧读数。
- Claude Code 的额度请求也使用较长间隔及失败退避；本地会话、确认提醒及 Token 监听保持原频率。
- `check-claude-subscription.sh` 通过：并发合并、随机间隔边界、连续手动刷新、失败保留、重启恢复冷却、账号隔离、成功恢复，以及 provider 和 UI 数据适配。
- `check-claude-desktop-usage.sh` 通过：包括 403、429、503、重定向、过期、账号隔离及凭据不输出。
- `check-agent-data.sh`、完整构建和严格签名验证通过。`check-ui.sh --claude-subscription` 的完整明暗用量卡片已检查，显示上次读数、实际更新时间及下次查询时间。

## 本机实际状态

安装包位于 `.build/claude-quota-cooldown/While AI Works.app`。此本机包保留已授权的 0.20.3 读取助手，SHA-256 为 `60d15f384ef6f2097ed0da807c224943112e17cbfd669eedbe22b116ce2474f7`，避免仅修改主程序调度就让用户重新授权；助手代码未改，旧协议与新主程序兼容。默认构建会重新链接助手，不能把其签名与这份本机验证包混为一谈。

安装时仅将刚刚真实发生的失败及时间带入新调度缓存，没有填入额度数据。实际启动、连续三次点击“重新检测”和重启后，缓存中的尝试时间与下次查询时间不变；系统日志中没有新的读取助手 HTTP 响应事件，没有授权弹窗。

最后一次真实远端查询仍为 HTTP 403。自动测试已验证未来成功读数能在临时失败时保留，但旧版已丢失的数据未被补造，真实额度恢复尚未通过。该状态不满足正式发布条件。

本机日志、脱敏结果与截图保存在 `.build/claude-quota-cooldown/`。
