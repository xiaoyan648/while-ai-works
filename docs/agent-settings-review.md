# Agent 设置页排查与调整方案

2026-10-24。图标替换和下述设置结构调整均已实现，本地 Preview 已更新。

## 已确认的问题

1. **行身份冲突导致显示错误。** `SettingsView.ai` 在同一个 Section 内先遍历全部 `WorkSource`，再遍历 Codex、Claude。两处使用相同的 `source.id`。原生 SwiftUI Form 最小复现中，下方交互行被上方关注行替代；仅给第二组行添加不同的 ID 后恢复正常。这解释了截图中的重复行和缺失开关，不能只靠调整间距解决。
2. **开关没有统一位置。** 每行使用带标签的 `Toggle`、`Spacer` 和不同宽度的操作控件。Form 自动布局与这些弹性控件叠加，使开关随按钮、文字宽度漂移；相同文字的 Hermes、DSH 行也可能采用不同的布局结果。
3. **空白行由分隔符产生。** `Divider()` 直接作为 grouped Form 的一行，形成了额外空白和很短的竖线。应该使用有标题的 Section 分组。
4. **两种接入能力被写成近似的设置。** Claude 的“安装监听”负责工作状态，“安装交互监听”负责授权请求，底层并非重复操作。但两者都叫监听，又在不同位置重复出现客户端名称，用户无法判断是否需要装两次。
5. **安装、关注、运行状态缺少区分。** Qoder、WorkBuddy、Claude 的状态监听按钮始终显示“安装监听”和“移除”；交互监听才会依据安装状态改变按钮。Hermes、DSH 按钮实际导出插件、复制命令并打开说明，不代表已经安装成功。

复现产物在 `.build/agent-marks/SettingsIdentityProbe.swift`、`settings-identity-false.png` 和 `settings-identity-true.png`。这是独立布局实验，不会写入用户设置。

## 已实施结构

将现有“跟随 AI”拆成三个职责明确的分组：

| 分组 | 内容 | 规则 |
| --- | --- | --- |
| 小游戏启动时机 | 随时开启 / 跟随 AI 工作 | 明确只控制小游戏，避免被理解为猫条的总开关 |
| 关注的 Agent | 图标与名称、接入摘要、配置按钮、关注开关 | 每个 Agent 只出现一次；配置与开关固定在右侧，所有行对齐 |
| 授权与提问 | 在猫条接收授权与提问 | 一个全局开关；说明只对已关注且支持交互的 Agent 生效 |

主列表统一呈现为：

```text
[图标] Codex        自动读取本地会话        [配置…]   [关注开关]
[图标] Claude Code  工作状态监听待配置      [配置…]   [关注开关]
[图标] Hermes       自动读取本地会话        [配置…]   [关注开关]
[图标] DSH          自动读取本地会话        [配置…]   [关注开关]
```

上述状态文字仅演示布局；实际值由检测结果决定。

“配置…”打开该 Agent 的详情，按能力显示“工作状态”和“授权与提问”。安装、重新安装、移除本应用接入配置放在这里。Codex 的自动读取能力用说明展示，Claude 的两类监听明确分开；Hermes、DSH 提供增强监听接入步骤与验证结果。不支持的能力直接说明，不画无效开关。

安装配置存在、已经收到事件、暂未验证是不同状态。导出插件或复制命令不能显示为“已接入”。不能可靠查询的账户额度不显示，不影响本机会话用量。

## 交互和验收要求

- 六个 Agent 各有且只有一个关注开关；开关只修改关注状态，不安装或卸载插件。
- 调整小游戏启动时机不清空猫条关注列表；关闭交互不影响状态和用量读取。
- 使用明确的行 ID 和统一行组件；名称与状态可换行，配置入口和开关始终对齐，不依赖透明占位按钮。
- 未安装时不显示移除；移除明确指向“本应用的接入配置”，避免被误认为卸载 Agent。
- 在 480、520、680pt 窗口宽度及深浅色下检查布局；点击各行只修改对应 Agent，滚动、重开窗口后行内容不互换。
- 用“本地读取可用、未接入、配置已写入但未收到事件、已验证接入”覆盖状态展示；不将“正在运行”与“已经安装”混用。


## 本轮验证结果

- `HookChecks`：71 项通过，新增覆盖未安装、完整配置、部分配置、客户端禁用、组件不可执行、配置格式错误。原有 `NativeHookMonitorChecks` 通过。
- `scripts/check-ui.sh --agent-settings`：480、520、680pt 的深浅色主列表，以及六个 Agent 的深浅色配置详情均生成原生渲染；人工检查窄窗口与宽窗口，按钮和关注开关对齐。隔离目录验证未接入与仅导出插件两种情况，不把导出当作已接通。
- 离屏渲染无法提供 AX 控件树，因此唯一性与点击行为另在真实 Preview 窗口验证，没有将离屏截图当作交互通过。
- 真实窗口中，六个关注开关、六个配置入口均各出现一次；逐一打开配置详情确认客户端对应正确。
- 逐一切换六个关注开关，仅对应 Agent 改变，随后均恢复。切换小游戏启动方式和交互总开关，关注列表保持不变。
- 临时关闭 Hermes 关注后，完整退出、重启 Preview，关闭状态仍保留；随后恢复原选择：Codex、Claude、Hermes、DSH 开启，Qoder、WorkBuddy 关闭。
- Hermes 配置详情的“重新检测”可用，并显示实际增强事件时间。未通过测试点击安装、移除等按钮修改原客户端配置。
- 完整应用构建与 Preview 签名校验通过。上述结果为发布前的本机验收记录；正式版打包与更新验收见 [0.20.0 发版验证](releases/0.20.0-validation.md)。

布局实现：`Sources/WhileAIWorks/AgentSettings.swift`。接入状态只在本机后台读取；不增加账户额度或网络请求。Hermes / DSH 的安装、重装和移除继续由原客户端按说明执行，保留 profile 和原审批机制。
