# 迭代经验与错题本

每轮迭代开始时，先阅读与本轮工作相关的条目；结束时，把实际发生且值得复用的错误补进本页。每条记录包括错误、影响、证据、修正、验证和下次检查点。没有新错误时，在当轮记录中说明即可。

条目使用稳定编号；同类错误再次发生时补充原条目的证据和检查点。私人反馈保留在原始有权限的来源，公开记录使用脱敏事实和可公开复现。候选、取舍和交付结果另见 [迭代流程](product-iteration.md)。

## L001：核实产品入口后再判断能力缺失

- **日期：** 2026-11-16。
- **错误：** 只查看当前会话工具和 DSH CLI 帮助，就把「当前工具未暴露周期任务接口」推断为需要另外提供调度器。
- **影响：** 提前阻塞了可以通过 DSH 原生自动化完成的配置，增加了一次不必要的人工往返。
- **证据：** [初始流程提交](https://github.com/xiaoyan648/while-ai-works/commit/6e1beb29d2d49fbb88a515c162a62b7274aef746) 写入了未接入调度器的结论；[修正提交](https://github.com/xiaoyan648/while-ai-works/commit/29e8e49249737d9324d24e75bb9a76f0a0e7e1fc) 改为 DSH 原生自动化的配置与运行边界。
- **修正：** 检查现有 Web 的「自动化任务」入口和已安装调度包文档，通过原生入口配置专用会话任务。
- **验证：** 创建前列表为空，创建后回读到一项每日任务，时间和时区正确。此验证只证明任务保存成功；到点投递和产品迭代执行结果需要另行核对。
- **下次检查点：** 遇到能力缺口时，分别确认当前 Agent 工具、产品 UI 和对应文档；报告缺口时明确是哪一层不可用。遇到实际权限拒绝仍按拒绝处理，不能通过另一个入口绕过限制。

## L002：区分目标操作的权限与 CLI 附带查询的权限

- **日期：** 2026-11-16。
- **错误：** 更新 PR 正文时直接依赖 `gh pr edit`，没有预料到该命令会查询额外的组织信息。
- **影响：** 命令因缺少 `read:org` 失败，但这并不意味着没有修改该仓库 PR 的权限。
- **证据：** CLI 返回 GraphQL `login` 字段需要 `read:org`；同一账户对目标仓库 PR 的 REST `PATCH` 成功，随后回读确认正文和可审阅状态。
- **修正：** 使用 `gh api repos/<owner>/<repo>/pulls/<number> --method PATCH -F body=@<file>`，只执行已授权的目标操作，不修改 token 权限。
- **验证：** [PR #6](https://github.com/xiaoyan648/while-ai-works/pull/6) 正文更新成功并转为可审阅；正文保留实际检查与运行限制。
- **下次检查点：** 先识别失败的是目标写入还是不必要的附带查询。只有已授权的更窄接口确实可用时才改用它；目标接口拒绝时保留错误并报告具体缺口。

## L003：下载重试前核对机器已有的网络配置

- **日期：** 2026-11-16。
- **错误：** 原生检查的依赖下载超时后，多次继续走同一条缓慢直连路径，直到检查系统代理才找到可用配置。
- **影响：** 重试没有消除根因，延迟了本轮原生验证。
- **证据：** Rive 下载首次返回 `curl: (56) Recv failure: Operation timed out`；后续直连仍只有每秒数十 KB。`scutil --proxy` 显示机器已有启用的 HTTPS 代理，但命令环境未设置对应代理变量。
- **修正：** 停止重复下载，仅在下载命令中使用机器已有代理，经 `gh release download` 获取官方固定版本。
- **验证：** Rive 6.27.0 和 Sparkle 2.10.0 下载成功，SHA-256 均与仓库固定值相同。
- **下次检查点：** 首次超时或持续低速时，先核对进程、已有网络配置和文件进度，再选择有边界的重试；继续验证官方来源和校验和。

## L004：独立调用构建片段时，检查前置工具和实际产物

- **日期：** 2026-11-16。
- **错误：** 为并行准备依赖，独立调用构建片段，遗漏了 `rg` 不在 `PATH` 的前提；外层命令最后的成功掩盖了片段中的编译失败。
- **影响：** Agent HUD 模块没有生成，却留下缓存标记，后续构建可能误以为依赖已就绪。
- **证据：** 输出包含 `rg: command not found` 和 `error: no input files`，但外层命令退出码为 0；标记文件存在，模块未生成。
- **修正：** 清除这次失败留下的标记，将已安装的 `rg` 所在目录加入该构建命令的 `PATH`，回到仓库完整构建入口。
- **下次检查点：** 优先使用项目构建入口。确需独立调用片段时，核对前置工具、错误输出和目标产物；外层退出码不能替代各阶段结果。

## L005：连续操作测试要重新建立每个用例的状态

- **日期：** 2026-11-16。
- **错误：** 本轮最初的 `pathDrafts()` 只在循环前选择一次会话，却假设两次发送都保留这个目标。
- **证据与影响：** 自审发现 `finishComposing()` 会恢复为记住的客户端；第二个用例会打开新会话，而非验证发到原会话的完整路径。此时失败反映的是测试设置错误。
- **修正：** 每次输入前重新选择同一个合成会话，再检查目标选择器没有打开、一次 Enter 发送，以及收到的正文与原路径完全一致。
- **下次检查点：** 编写多次交互的测试时，追踪成功路径的状态清理；每个独立用例显式建立前置状态，保留对实际交付结果的断言。
