# 快捷输入：方向与设计

状态：M1 实现中，方向、UI、交互和动画已敲定，2026-11-01。分支 `feat/quick-input`，基于 `dadb0c6`（0.20.4-beta.1）。此前的讨论稿见工作目录外层 `docs/waw-command-input-plan-2026-10-30.md`。

可交互原型：<https://claude.ai/artifact/HxQY2uV3TybnEMm9JgoMoZ>（默认私有，分享给同事需在页面的 Share 菜单操作）。

## 结论

在任何应用里按一下快捷键，用一句话把事情交给 Agent，然后回到手头的事。之后的进度、提问和结果都由现有猫条接手。

这样 WAW 的工作流就连成了一条线：发起 → 等待（玩） → 处理提问 → 看结果。WAW 负责投递和看护，对话本身仍留在 Agent 自己的客户端。

讨论稿的技术判断大多成立，产品上有三处需要收：

| 讨论稿 | 问题 | 调整 |
| --- | --- | --- |
| 一期同时做全局输入、两个可执行目标、Jev、Agent 决策器、两个工具 | 八块交付，先验证不了最关键的问题：大家会不会真的用它发任务 | 一期只做投递。模型路由放二期，小工具放三期 |
| 输入框上方三个标签，下方三个控件，⌘↵ 发送 | 像配置表单，看不出交给谁，也看不出按下后发生什么 | 收成一句话：「交给 Codex 在 CineFlow 开新任务」，按钮写实际动作 |
| 新任务靠 WAW 启动 Agent 进程 | 进程归属、断线、审批都要 WAW 负责，容易滑向自研聊天客户端 | 新任务默认「带到客户端」，后台开工逐个 Agent 验证后再开放 |

## 做什么，不做什么

**做**

- 全局唤起，一句话发起，关闭后回到原应用。
- 让用户在发送前看清谁来做、在哪个项目、发送后会发生什么。
- 继续猫条里能接收消息的会话。
- 发送后给出真实回执，交给猫条跟进。
- 用 WAW 已有的本地数据帮用户选目标：上次选择、项目历史、额度、是否忙碌。

**不做**

- 不做聊天客户端：不展示完整对话、流式输出和 diff。详情回原客户端看。
- 不做 Agent 运行时或模型网关：不持有模型 Key 替用户跑任务，不替 Agent 决定权限，不自动批准。
- 不改 Agent 的会话历史文件来驱动执行。
- 不做多 Agent 编排、工作流、一次发给多个 Agent。
- 不做通用启动器：不搜文件、不开应用，不和 Raycast 比工具数量。
- 不做 Skill 管理：不安装、不编辑、不跨 Agent 转换，只发现和调用。
- 不让模型同时猜 Agent、项目、会话和 Skill。
- 不默认把任务内容发给第三方。模型路由必须用户主动开启，并在输入框里写明。
- 近期不做插件市场。

## 交互设计

### 一句话模型

用户只回答一件事：交给谁。其余信息由这个选择带出来。

```text
交给 Codex ⌄ 在 CineFlow ⌄ 开新任务                带到 Codex ↵
继续 修复充值边界 ⌄  CineFlow · 运行中      排队 ⌘↵  插入当前步 ↵
```

- 选 Agent 等于开新任务，这时才需要项目。
- 选会话等于同时确定 Agent、项目和续接，项目不可改。因此不需要独立的「会话」控件。
- `@` 列表同时列出 Agent 和会话，并标明额度、运行状态和能力限制。不能接收消息的目标照样显示，并说明原因。

### 符号

| 输入 | 含义 | 阶段 |
| --- | --- | --- |
| `@` | 谁来做（Agent 或会话） | 一期 |
| `#` | 哪个项目 | 一期 |
| `/` | 一期原样发给目标 Agent，例如 `/review` | 一期 |
| `/` | 打开列表，分组显示目标 Agent 的技能和 WAW 工具 | 二、三期 |

符号都可不用，句子里的标签同样能点。选中后生成结构化目标，并从正文移除，正文里的邮箱和路径不会被当成指令。

### 键盘

- Enter 发送，⇧Enter 换行。这和 Claude Code、Codex、ChatGPT、Raycast 的习惯一致。讨论稿的 ⌘Enter 主要防误发；这里改为始终显示目标来防。
- 中文输入法组词期间，Enter 只确认候选词，不发送。
- **Enter 永远推进下一步**：缺 Agent 就打开 Agent 列表，缺项目就打开项目列表，内容不丢。
- 运行中的会话：Enter 插入当前步，⌘Enter 排队。
- 列表打开时，↑↓ 移动，Enter 或 Tab 选中，Esc 关闭列表。
- 列表关闭时，Tab 打开目标列表，Esc 收起面板并保留草稿。
- 默认快捷键 ⌥Space，可配置。现有 ⌘⇧Space 已用于开关桌面游玩；注册失败时沿用现有的冲突提示。

### 默认目标

讨论稿提出没配路由时弹选择器。这样每次发送都要多一步，所以改为：

1. 第一次使用选一次 Agent 和项目。
2. 之后默认用上次选择，项目优先取「这个项目上次用的 Agent」。
3. 从猫条会话卡片唤起时，直接带上该会话。
4. 目标始终显示在句子里，绝不默默发给列表第一项。

这就是一期的「路由」：规则都在本地，不需要配置和网络。`@agent1` 这类别名放到后续。

### 按钮写实际动作

| 按钮 | 实际发生 | 回执 |
| --- | --- | --- |
| 带到 Codex / 带到终端 | 打开客户端并填好内容，用户自己发送（M1 的新任务） | 已带到 Codex，等你发送（不算送达） |
| 继续 | 在空闲的原会话开始新一轮 | 已送达原会话 |
| 插入当前步 | 插入运行中的当前这一步 | 已插入当前这一步 |
| 排队 | 当前这一轮结束后再发送 | 已排队，这一轮结束后发送 |
| 后台开工 | 后台启动，不开窗口（M2） | 交给 Codex 了 |

按钮文字是预期动作，回执写实际结果。例如按「插入当前步」时这一轮恰好结束，实际开了新一轮，回执就写「已送达原会话」。

### 运行中的会话

| 按键 | 行为 | 适合 |
| --- | --- | --- |
| Enter | 插入当前这一步 | 补充和纠正。Agent 下一步就能看到，已完成的工作不丢 |
| ⌘Enter | 排队，这一轮结束后发送 | 下一件事，不想影响当前工作 |
| 面板不提供 | 打断并重开 | 回原会话操作 |

- 默认选插入，因为大多数补充都和当前任务有关，而且纠正类内容排队就晚了。据第三方资料，Codex CLI 也是回车插入、Tab 排队；桌面端的默认值尚未确认。
- 排队是常用的第二选择，所以两个动作并排显示按键，不用记。
- 不提供打断：用户在别的应用里看不到 Agent 做到哪一步，打断却会丢掉进行中的工作。Codex 桌面端虽有 `thread-follower-interrupt-turn`，面板里也不开放。
- 会话正在等审批或回答时不接收消息，提示用户先在猫条处理。

排队由 WAW 暂存，猫条图标上显示数量。连续两次读到会话空闲才发送，一次安静不算结束；发送走现有的 `thread-follower-start-turn`。会话消失时内容回到草稿；WAW 重启后暂存内容也恢复成草稿，不自动发送。

Codex 桌面端有自己的队列（`thread-follower-set-queued-follow-ups-state`，设置项 `followUpQueueMode`），但安装包里的实现是用传入的列表替换整个队列，读取接口和消息格式都未公开。写错会冲掉用户在客户端里排好的内容，所以 M1 不用。代价是排队内容不显示在客户端里。

### 材质

选定玻璃，灰色实块只作回退。

- 面板用 `NSVisualEffectView`（`.hudWindow`，`behindWindow`，`active`），外加 0.5 pt 渐变描边。系统开启「减少透明度」时由系统自动回退。现有猫条的 `PanelMaterial` 默认实色，它常驻屏幕边缘；快捷输入是临时面板，默认玻璃，不新增设置。
- 面板内不用灰底块。标签平时只是文字和小箭头，悬停才有底色；只有列表选中行用淡底。
- 列表长在同一张面板里，输入框和底栏之间展开，不另开一张卡片。
- 品牌绿只用于主操作的 ↵ 键帽和状态文字，其他都靠文字层级区分。
- 底栏随状态变化：平时是一句话加动作，列表打开时是「↑↓ 移动、esc 返回」加「选择 ↵」。说明文字只在确有必要时出现。
- 字号：输入 19 pt，列表和底栏 13–14 pt，分组标题 11 pt。

### 动画

沿用 `Motion` 的节奏。开启「减弱动态效果」时全部退化为短淡入淡出。

| 时机 | 效果 | 时长 |
| --- | --- | --- |
| 唤起 | 淡入，下移 6 pt，不回弹。系统玻璃不能随窗口缩放，所以不做原型里的 0.97 缩放 | 0.18 s |
| Esc 收起 | 淡出 | 0.14 s |
| 展开列表 | 面板向下展开，内容淡入。方向键移动选中行不做动画 | 0.2 s |
| 发送（继续、插入、排队、后台开工） | 面板淡出，内容收成一枚小标签，沿弧线飞向对应 Agent 的猫条图标 | 0.46 s |
| 标签到达 | 图标弹一下（放大到 1.22），回执从猫条旁滑出 | 0.42 s |
| 带到客户端 | 面板淡出，不飞向猫条，因为接下来要看的是客户端窗口 | 0.14 s |
| 没送到 | 图标轻轻左右晃一次，回执留着不消失 | 0.36 s |
| 回执消失 | 成功类 4 秒后自动淡出，待确认和失败需要用户处理 | — |

发送不等对方回执：面板立刻离开，回执先显示「正在发送…」，再更新为实际结果。

### 位置与回执

- 面板在屏幕中上方，宽 640 pt，不依赖猫条停靠边，宠物模式下也能用。
- 使用不激活原应用的可聚焦面板。前台应用不变，关闭后焦点自然回去。「带到客户端」例外，客户端会到前台。
- 回执贴在猫条旁，告诉用户接下来去哪里看。
- 结果不明时沿用 `AgentMessageOutcome.uncertain`：不重发、不改投，保留内容，并在下次打开时提醒可能重复执行。
- 失败时保留内容。

### 路由（二期）

- 句子里的 Agent 标签可以选「自动选择」。显式 `@` 永远绕过路由。
- 开启前说明任务文字会发给哪个服务；开启后输入框持续显示这一点。
- **系统替你选的，给你反悔窗口；你自己选的，立刻执行。** 自动选择后有 3 秒「改给别人 / 取消」，再开始执行。
- 拿不准或失败时打开候选列表，内容不丢。
- 先让用户看到足够多的手动选择记录，再决定要不要做。如果「记住上次」的改选率已经很低，模型路由的价值就不大。

### 小工具（三期）

小工具和投递链路互不依赖，所以它们验证不了投递，放后面不影响主线。

- 选中 `/json`、`/time` 后面板切到工具模式：句子变成「WAW 工具 · /json」，结果就地显示，Enter 复制。目标消失，一眼能看出没有 Agent 参与。
- `/` 列表分组标明来源。WAW 工具和 Agent 技能在内部是不同类型，同名也不会混淆。
- 之后可加粘贴识别：粘贴 JSON 或时间戳时直接提示对应工具，无需记命令。

## 各 Agent 的投递能力

依据：本机 Codex CLI 0.164.0、Claude Code 2.1.301、Hermes 0.22.5、DSH 0.2.1-rc.2 的命令帮助，Codex 生成的协议文件，Codex 桌面端 26.1027 安装包（`/Applications/ChatGPT.app`）里的方法名，官方文档和本仓库代码。除已实现的发送外，这些都还没有做过实际任务验证。桌面端 IPC 不是公开接口，可能随版本变化。

| 目标 | 继续已有会话 | 新任务：带到客户端 | 新任务：后台开工 |
| --- | --- | --- | --- |
| Codex | **已实现**：`CodexOriginalConversation.send`，走桌面 IPC 并核对回执；空闲时开新一轮，运行中插入当前步。排队待接入 | [`codex://new?prompt=&path=`](https://learn.chatgpt.com/docs/reference/commands)，只填入，不发送 | App Server 有 `thread/start`、`turn/start`、`turn/steer`、`skills/list`，但 CLI 帮助标为 experimental |
| Claude Code | 未接入，回原客户端 | [`claude-cli://open?cwd=&q=`](https://code.claude.com/docs/en/deep-links)，只填入，`q` 最长 5000 字符，需已注册链接处理器 | `claude -p` 可用，**但审批是风险**，见下 |
| Hermes | 未接入 | 未查到官方深链；可打开终端运行 `hermes chat --in DIR` | `hermes chat --query-file - --in DIR --format stream-json`，审批待验证 |
| DSH | 未接入 | 可打开终端并使用恢复命令；新建待验证 | headless profile 的 `--json` 与 `--session-id`，审批待验证 |

### 后台开工的主要风险

1. **审批断链**：WAW 的 Claude 审批依赖 `PermissionRequest` hook。[社区报告](https://claudeissues.com/issue/88328-permissionrequest-hooks-never-fire-in-print-mode-on-2-1-237-while-a-pretooluse-c)称它在 `claude -p` 下不触发，尚未在官方文档或本机确认。若属实，后台 Claude 任务遇到工具授权时猫条收不到请求。不能用跳过权限来绕开。
2. **进程归属**：WAW 退出或自动更新时，子进程不能跟着死，也不能变成无人看管的孤儿。Codex 的 daemon 模型较合适，`claude -p` 要单独处理。
3. **可续接性**：后台任务需要出现在原客户端的会话列表里，用户才能接手。Codex 的 thread 能否进入桌面端列表需要验证。
4. **用户配置差异**：WAW 直接调用可执行文件，不经过 shell 别名。例如用户在 zsh 里给 `claude` 配的参数不会生效，权限行为可能和终端不同。

因此一期默认「带到客户端」，后台开工按 Agent 逐个开放，过了下面的验证才算支持。

## 分期

| 阶段 | 交付 | 进入下一阶段的条件 |
| --- | --- | --- |
| M1 投递最小闭环 | 全局面板、玻璃材质与动画、草稿、输入法、`@` `#`、项目列表、记住上次；继续和插入 Codex 会话（复用现有 IPC）；排队；Codex、Claude Code 新任务带到客户端；回执进猫条 | 团队连续用一周，看每天唤起次数和发送完成率 |
| M2 后台开工 | 先做 Codex App Server，验证通过后再做 Claude Code 或 Hermes；分发记录；从猫条卡片唤起并带上会话 | 目标 Agent 通过下面四项验证 |
| 二期 | 模型路由（Jev 或 Agent）、Skill 发现与调用、Hermes / DSH 接入、文件和选中文本附件 | 手动选择数据显示确实需要路由 |
| 三期 | `/json` `/time` 等本地工具、粘贴识别、`/plugin` 管理入口 | 面板已成为日常入口 |

后台开工的验证项：能在指定目录启动；审批和提问能到猫条；WAW 重启后任务继续且状态能恢复；能在原客户端接手。

## 技术骨架

```text
QuickInputPanel（NSPanel，nonactivating，可聚焦）
  └ QuickInputModel：draft、target、project、picker
       └ TargetResolver：Agent + 会话 + 能力 + 额度 → @ 列表与默认目标
            └ DispatchAdapter（每个 Agent 一个）
                 capabilities：continueSession / handoff / background / skills
                 dispatch(request) → DispatchOutcome
                      └ DispatchRecord → 猫条回执
```

- `DispatchOutcome` 由现有 `AgentMessageOutcome` 扩展而来，增加 `handedOff`，和 `accepted` 严格区分。
- 界面只开放 adapter 声明支持的动作，按钮文案由所用动作决定。
- 用户文本走参数数组、标准输入或 URL 编码，不拼 shell 字符串。深链要处理长度上限，超长时提示并回退到复制。
- 全局快捷键新增独立注册 ID，和现有 `InteractionShortcut` 的 ID 1、2 分开。
- 分发记录只存目标、时间和状态，不存任务全文，以符合本地和隐私承诺。草稿只在内存里；排队内容在发送或取消前暂存在本机偏好设置，之后删除。

## 验证

`bash scripts/check-quick-input.sh [--snapshot 目录]`。需先运行 `bash scripts/build.sh`。

### 待确认

1. 不激活的 NSPanel 里，中文输入法组词、候选窗和 Enter 拦截是否正常。`scripts/check-quick-input.sh` 已覆盖组词状态下 Return 不发送；真实拼音输入待真机确认。
2. `claude -p` 下 `PermissionRequest` 和 `PreToolUse` 是否触发，WAW 的审批能否回传。
3. App Server 创建的 thread 是否出现在 Codex 桌面端列表和 WAW 的会话读取中，WAW 能否续接。
4. 深链打开时焦点去向，以及未注册 `claude-cli://` 时的表现和引导。
5. `.hudWindow` 玻璃在亮色文档、深色壁纸、深浅两种外观下的文字可读性。

## 验收

- 未配置任何路由也能完整使用。
- 显式选择的目标不会被覆盖。
- 发送前能看清目标和动作，发送后回执与实际一致。
- 「带过去」不会显示为已送达。
- 失败或结果不明时内容不丢，也不自动重发或改投。
- 关闭面板不影响已送达的任务，前台应用不变。
- 输入法组词时不会误发送。
- 运行中的会话：Enter 只插入，⌘Enter 只排队，取消排队后内容回到草稿，面板里没有打断入口。
- 开启「减少透明度」和「减弱动态效果」后，面板可读且动画退化。
