# 快捷输入：方向与设计

状态：M1 随 0.21.0 发布，2026-11-02。此前的讨论稿见工作目录外层 `docs/waw-command-input-plan-2026-10-30.md`。

可交互原型：<https://claude.ai/artifact/HxQY2uV3TybnEMm9JgoMoZ>（默认私有，分享给同事需在页面的 Share 菜单操作）。原型停在两栏选择那一版，按键规则以本文为准。

## 结论

在任何应用里按一下快捷键，用一句话把事情交给 Agent，然后回到手头的事。之后的进度、提问和结果都由现有猫条接手。

为什么要做：模型能独立完成的工作越来越多，多任务的瓶颈正在转向人的注意力（DeepSeek Harness 团队，[《Super-agent 设计探索》](https://mp.weixin.qq.com/s/zoS7GlReWPhfCjENGxXCdg)，据其观察，一个人通常只能同时跟进 3 到 5 个活跃会话）。猫条已经把进度和卡点收到一处，缺的是统一的发起入口。快捷输入补上它，让注意力只放在这两处。

这样 WAW 的工作流就连成了一条线：发起 → 等待（玩） → 处理提问 → 看结果。WAW 负责投递和看护，对话本身仍留在 Agent 自己的客户端。我们借的是文章对瓶颈的判断，不是它的架构：文章主张把 Session 藏到系统内部，WAW 不接管执行，会话仍然可见、可选。

讨论稿的技术判断大多成立，产品上有三处需要收：

| 讨论稿 | 问题 | 调整 |
| --- | --- | --- |
| 一期同时做全局输入、两个可执行目标、Jev、Agent 决策器、两个工具 | 八块交付，先验证不了最关键的问题：大家会不会真的用它发任务 | 一期只做投递。模型路由放二期，小工具放三期 |
| 输入框上方三个标签，下方三个控件，⌘↵ 发送 | 像配置表单，看不出交给谁，也看不出按下后发生什么 | 收成一句话：「交给 Codex 在 CineFlow 开新任务」，按钮写实际动作 |
| 新任务靠 WAW 启动并持有 Agent 进程 | 进程归属、断线、审批都要 WAW 负责，容易滑向自研聊天客户端 | 新任务在真实终端里启动，进程不归 WAW，审批和接手都走客户端原有能力 |

## 做什么，不做什么

**做**

- 全局唤起，一句话发起，关闭后回到原应用。
- 让用户在发送前看清谁来做、在哪个项目、发送后会发生什么。
- 继续猫条里能接收消息的会话。
- 发送后给出真实回执，交给猫条跟进。
- 用 WAW 已有的本地数据帮用户选目标：上次选择、项目历史、额度、是否忙碌。

**不做**

- 不做聊天客户端：不展示完整对话、流式输出和 diff。详情回原客户端看。
- 不做 Agent 运行时或模型网关：不持有模型 Key 替用户跑任务，不替 Agent 决定权限，不自动批准。
- 不改 Agent 的会话历史文件来驱动执行。
- 不做多 Agent 编排、工作流、一次发给多个 Agent。
- 不做通用启动器：不搜文件、不开应用，不和 Raycast 比工具数量。
- 不做 Skill 管理：不安装、不编辑、不跨 Agent 转换，只发现和调用。
- 不让模型猜 Skill。Router Agent 第一版只选一个目标（Agent 加工作区或会话）。
- 不默认把任务内容发给第三方。Router Agent 必须用户主动开启，并在输入框里写明。
- 近期不做插件市场。

## 交互设计

### 一条规则

**回车就行，想看现场加 ⌘。**

- **Enter 用最省事的方式交出去**：能直接发就发，人留在原地，不打断注意力；不能发就带过去，内容跟着走；没写内容就是打开。
- **⌘Enter 跟过去**：内容带到对方那里，不发送。只在和 Enter 不同时显示。
- **列表打开时 Enter 只选中**，选目标绝不会把内容发出去。选好后再按一次 Enter 才发。`#关键词 ⌘↵` 直接跳过去，是快捷路由。

按钮写实际动作：

```text
用 Codex CLI ⌄ 在 CineFlow ⌄ 开新会话               打开 ⌘↵   发送 ↵
用 Codex ⌄ 在 CineFlow ⌄ 开新会话                            带过去 ↵
用 Codex ⌄ 继续 修复充值边界 ⌄  CineFlow · 运行中    打开 ⌘↵   发送 ↵
```

### 六个对象

桌面端和命令行能做的事不同，所以分开。没装的不显示。DSH 只打开已有会话，它自己开新会话。

**Agent 决定用什么打开，会话决定继续哪段对话。** 同一家的客户端读同一份会话，所以列表按厂商筛选：选 Codex 或 Codex CLI 看到的都是 Codex 的全部会话，Claude 同理。不同厂商的会话互相打不开，不列出来。

| 目标 | Enter | ⌘Enter |
| --- | --- | --- |
| Codex CLI、Claude Code、Hermes 新会话 | 发送，终端里启动并提交第一句，留在原地 | 打开终端，内容复制 |
| Codex CLI、Claude Code 打开任一个已结束的同家会话 | 恢复并发送，留在原地 | 恢复，内容复制 |
| Codex 打开命令行开的会话 | 带过去，内容填入输入框 | 无 |
| Claude 打开 Claude Code 开的会话 | 带过去，导入后内容复制（链接不收内容） | 无 |
| Codex 桌面端已有会话 | 发送，运行中则插入当前步，留在原地 | 打开，内容填入输入框 |
| Codex、Claude 桌面端新会话 | 带过去，内容填入输入框 | 无 |
| Claude 桌面端已有会话 | 带过去，内容复制（它的链接不收内容） | 无 |
| 进程还开着的会话（不管选了谁） | 带过去，回到它所在的地方，内容复制 | 无 |
| 没进猫条的旧 Codex 桌面会话，选 Codex | 带过去，内容填入输入框（没有在线的 owner，发不了） | 无 |
| 等你处理的会话 | 带过去，内容复制，不插话 | 无 |
| Claude Code 未登录 | 带过去，内容复制 | 无 |

能填就填，不能填才复制。这里不针对任何终端定制：往运行中的终端面板里打字只有个别终端支持，所以不做。

### 打开一个会话

依次尝试，所以旧会话也不是死角：

0. 选的 Agent 不是开这个会话的客户端，且没有进程占着它：用选的 Agent 打开。终端用恢复命令，Codex 用 `codex://threads/ID`，Claude 用 `claude://resume?session=ID`。

否则：

1. 会话自己记录的入口（Codex、Claude 桌面端，iTerm 面板）。
2. 进程还开着：把它所在的终端带到前面。从进程往上找所在的应用；终端用后台服务托管会话时找不到，就带默认终端。到不了具体面板。
3. 没在运行就在默认终端里恢复（`codex resume`、`claude --resume`，或会话记录的恢复命令）。
4. 还在运行但没有进程信息：内容复制，提示回到它所在的窗口。这是唯一到不了的情况。

连恢复命令都没有的会话不列出来。进程还开着的会话不恢复，哪怕正空闲，两个进程会同时写一个会话。是否还开着问的是 Agent 而不是终端：Claude Code 在 `~/.claude/sessions/` 登记进程，Codex 进程开着自己的会话日志。Codex 的共享后台服务（`app-server-daemon`）不算：所有客户端离开后它仍开着日志，新的客户端是接入同一个线程，而不是一起写。两个窗口接同一个线程实测一条消息只收到一次、回复一次。代价是通过它连着的终端窗口查不出来，只有运行中的状态能挡住，空闲时会再开一个窗口接上去。

同家互开的实测（2026-11-01，只打开，不发消息）：`codex resume` 打开桌面端会话，完整显示历史；`codex://threads/ID` 打开命令行开的会话，桌面端接管其日志；`claude://resume?session=ID` 导入后出现 `local_ID.json`；`claude --resume ID` 能认出桌面端会话并询问是否恢复（这台 Mac 的命令行未登录，没走到发送）。注意 `codex resume` 打开时会往日志追加一条设置记录。

### 符号

| 输入 | 含义 |
| --- | --- |
| `@` | 谁来做，六个对象。已选会话时换同家的另一个，会话不变；换别家，回到新会话 |
| `#` | 在哪里做，左栏工作区，右栏该工作区的会话 |
| `/` | 目前原样发给目标；之后分组显示技能和 WAW 工具 |

符号都可不用，句子里的标签同样能点。列表不管怎么打开（打字、点标签、回车补齐）都一样：触发符号进入输入框，打字就是搜索，选中或 Esc 后自动移除。选中后生成结构化目标，并从正文移除，正文里的邮箱和路径不会被当成指令。没有匹配时列表自动关闭，文字原样保留。

`#` 的两栏：

- 上下键换工作区，右栏跟着变；鼠标移动到工作区上同样聚焦。面板在静止的鼠标下打开时不会抢走键盘焦点。
- → 进入会话栏，← 返回。
- 搜索匹配工作区名（不含路径）和会话标题，范围是本机全部记录里当前厂商的部分。只命中会话标题时，光标直接落在该会话上，回车不会误开新会话。搜不到时列表关闭，底栏提示按 @ 换 Agent。
- `#关键词 ⌘↵` 直接跳到会话，`#关键词 ↵ ↵` 选中后发送。
- 列表只列当前厂商的会话，标题写明，比如「cineflow 的 Codex 会话」。换厂商看 `@`。
- 左栏第一行是「全部会话」：当前厂商在所有工作区的会话，也包括没有工作区的。还没选 Agent 时才是所有厂商。右栏第一行是「开新会话」（「全部会话」和 DSH 下没有）。
- 猫条里的会话排在前面，顺序和猫条一致（`AppState.sessionRows`）：等你处理、24 小时内完成、运行中、最近。其余按更新时间。工作区同样，最近用过的跟在猫条之后，再往后是记录里的。
- 浏览最多显示 50 条，超出的在列表底部写明还有多少条，靠搜索找。不分页：50 条够日常，再多翻页不如直接搜。
- 记录在唤起时后台读取，只读本机，不上传：Codex 的 `state_*.sqlite`（排除归档、子任务、`exec` 和日志已不存在的），Claude 的 `~/.claude/projects/*/*.jsonl`（只读首尾各 64KB，按修改时间缓存，最多 500 个），Hermes 的 `state.db`。DSH 没有记录可读，只有猫条里的。目录已不存在又没有其他入口的不列。
- 列表只写状态（运行中、等你处理、空闲），能做什么看底栏的按键。

### 键盘

- Enter 交出去，⌘Enter 跟过去，⇧Enter 换行，Esc 先关列表再收起面板并保留草稿。
- 中文输入法组词期间，Enter 只确认候选词，不做别的。
- **信息不够时 Enter 带你补齐**：缺 Agent 打开 Agent 列表，缺工作区打开工作区列表，内容不丢。
- 没有列表时 Tab 打开 Agent 列表。列表里 Tab 和 Enter 一样只选中。
- 默认快捷键 ⌥Space，可配置。现有 ⌘⇧Space 已用于开关桌面游玩；注册失败时沿用现有的冲突提示。

### 默认目标

讨论稿提出没配路由时弹选择器。这样每次发送都要多一步，所以改为：

1. 第一次使用选一次 Agent 和工作区。
2. 之后默认用上次选择，对象优先取「这个工作区上次用的」；已用 `@` 选过就不变。
3. 目标始终显示在句子里，绝不默默发给列表第一项。

这就是一期的「路由」：规则都在本地，不需要配置和网络。`@agent1` 这类别名放到后续。

### 终端里怎么启动

在用户的默认终端里运行 Agent 的交互模式。macOS 没有真正的系统级默认终端，这里的默认指系统打开 `.command` 脚本用的应用，Otty 等终端的「设为默认」改的也是它。WAW 运行 `open 脚本`，不维护优先级，也没有设置项。系统终端实测可行，其他终端未逐一实测。

唯一的例外是 Otty：它把打开的脚本当文件查看，不运行，所以默认终端是 Otty 时用 `otty-cli open 目录 --command 脚本` 启动。这是启动方式的一行分支，其他能力一律不针对任何终端定制。

- 交互模式保留了审批和 hook，也让用户随时能接手。进程不归 WAW，WAW 退出或更新不影响任务。
- 提示词写入 0600 的临时文件，由 0700 的脚本读取后立刻删除，shell 和终端都不解析它。运行期间提示词会出现在进程参数里。没运行的脚本和提示词文件保留一小时，下次启动时清理。
- 发送时终端可能短暂到前台（实测 Otty 不会）。脚本一运行就删除自身，WAW 看到文件消失立刻把前台还回去，最长等 8 秒。不同终端需要的时间不同，所以由脚本发信号，不猜时间。
- 每次唤起时在后台查 `claude auth status` 和进程还开着的会话。Claude Code 未登录时不提供发送，否则它会在看不见的终端里报 `Not logged in`，回执却写「交给 X 了」。
- 发送的回执先写「正在启动」。看到该客户端在该目录出现新会话，或被恢复的会话重新运行，才写「交给 X 了」；25 秒没有出现就提示可能在等确认（比如信任目录），并提供「打开终端」。

### 材质

选定玻璃，灰色实块只作回退。

- 面板用 `NSVisualEffectView`（`.hudWindow`，`behindWindow`，`active`），外加 0.5 pt 渐变描边。系统开启「减少透明度」时由系统自动回退。现有猫条的 `PanelMaterial` 默认实色，它常驻屏幕边缘；快捷输入是临时面板，默认玻璃，不新增设置。
- 面板内不用灰底块。标签平时只是文字和小箭头，悬停才有底色；只有列表选中行用淡底。
- 列表长在同一张面板里，在输入框和底栏之间展开，不另开一张卡片。窗口顶边不动，底栏贴着窗口底边走。
- 品牌绿只用于主操作的 ↵ 键帽和状态文字，其他都靠文字层级区分。
- 底栏随状态变化：平时是一句话加动作，列表打开时是「↑↓ 移动、esc 返回」加「选择 ↵」。说明文字只在确有必要时出现。
- 字号：输入 19 pt，列表和底栏 13–14 pt，分组标题 11 pt。

### 动画

沿用 `Motion` 的节奏。开启「减弱动态效果」时全部退化为短淡入淡出。

| 时机 | 效果 | 时长 |
| --- | --- | --- |
| 唤起 | 淡入，下移 6 pt，不回弹。系统玻璃不能随窗口缩放，所以不做原型里的 0.97 缩放 | 0.18 s |
| Esc 收起 | 淡出 | 0.14 s |
| 展开、收起列表 | 窗口向下展开，底栏跟着走，列表在中间露出 | 展开 0.2 s，收起 0.14 s |
| 移动选中项 | 高亮滑到新位置，不跳 | 0.16 s |
| ⌘Enter 发送 | 面板淡出，内容收成一枚小标签，沿弧线飞向对应 Agent 的猫条图标 | 0.46 s |
| 标签到达 | 图标弹一下（放大到 1.22），猫耳朵抖一下，回执从猫条旁滑出 | 0.42 s |
| Enter 打开 | 面板淡出，不飞向猫条，因为接下来要看的是客户端窗口。内容填好了就没有回执，复制了才提示 | 0.14 s |
| 没送到 | 图标轻轻左右晃一次，回执留着不消失 | 0.36 s |
| 回执消失 | 成功类 4 秒后自动淡出；待确认和失败留着，可点「知道了」关闭 | — |

发送不等对方回执：面板立刻离开，回执先显示「正在发送…」或「正在启动…」，再原地更新为实际结果。

### 位置与回执

- 面板在屏幕中上方，宽 640 pt，不依赖猫条停靠边，宠物模式下也能用。
- 使用不激活原应用的可聚焦面板。前台应用不变，关闭后焦点自然回去。Enter 打开时，目标客户端会到前台。
- 回执贴在猫条旁，告诉用户接下来去哪里看。
- 结果不明时沿用 `AgentMessageOutcome.uncertain`：不重发、不改投，保留内容，并在下次打开时提醒可能重复执行。
- 失败时保留内容。

### Router Agent（二期，未实现）

手动选择和 Router Agent 共用同一个入口。第一版只为一句话选一个目标，显式的 `@`、`#` 永远优先。它只负责分派，进度和回复仍由各 Agent 和猫条承接，不像《Super-agent 设计探索》里的 Router 那样保持全局上下文、统一对外回复。一次拆给多个 Agent 仍在「不做」之列，要做时先改这一条。

- 句子里的 Agent 标签可以选「自动选择」。显式 `@` 永远绕过路由。
- 开启前说明任务文字会发给哪个服务；开启后输入框持续显示这一点。
- **系统替你选的，给你反悔窗口；你自己选的，立刻执行。** 自动选择后有 3 秒「改给别人 / 取消」，再开始执行。
- 拿不准或失败时打开候选列表，内容不丢。
- 先让用户看到足够多的手动选择记录，再决定要不要做。如果「记住上次」的改选率已经很低，Router Agent 的价值就不大。

### 小工具（三期）

小工具和投递链路互不依赖，所以它们验证不了投递，放后面不影响主线。

- 选中 `/json`、`/time` 后面板切到工具模式：句子变成「WAW 工具 · /json」，结果就地显示，Enter 复制。目标消失，一眼能看出没有 Agent 参与。
- `/` 列表分组标明来源。WAW 工具和 Agent 技能在内部是不同类型，同名也不会混淆。
- 之后可加粘贴识别：粘贴 JSON 或时间戳时直接提示对应工具，无需记命令。

## 各客户端的依据

依据：本机 Codex CLI 0.164.0、Claude Code 2.1.301、Hermes 0.22.5 的命令帮助和实测，Codex 桌面端 26.1027 安装包（`/Applications/ChatGPT.app`）里的方法名，官方文档和本仓库代码。桌面端 IPC 不是公开接口，可能随版本变化。

- Codex 桌面端：新对话用 [`codex://new?prompt=&path=`](https://learn.chatgpt.com/docs/reference/commands)，只填入不发送。已有会话发送走 IPC 并核对回执，打开用 `codex://threads/ID?prompt=` 填入，这个参数来自应用代码，文档只写了新对话。
- Codex CLI：优先用桌面端自带的引擎，`codex -C 目录 -- 提示词`，恢复用 `codex resume -C 目录 ID -- 提示词`。桌面端和命令行的线程在同一个库里，`source` 分不开，开它的客户端看日志首行的 `originator`。
- Claude 桌面端：`claude://code/new?folder=&q=`，来自应用的链接处理代码和 Finder 服务，官方文档没写，版本更新后可能变化。只填入，也没有公开的发送接口。
- Claude Code：`claude -- 提示词`，恢复用 `claude --resume ID -- 提示词`。不用官方的 [`claude-cli://`](https://code.claude.com/docs/en/deep-links) 深链，它用自己记住的终端，不跟随系统默认。
- Hermes：`hermes chat --in 目录 --query=提示词`。

为什么不走这些路：

- `claude -p`：WAW 的 Claude 审批依赖 `PermissionRequest` hook，[社区报告](https://claudeissues.com/issue/88328-permissionrequest-hooks-never-fire-in-print-mode-on-2-1-237-while-a-pretooluse-c)称它在 `-p` 下不触发。交互模式没有这个问题。
- Codex App Server：CLI 帮助标为 experimental，建出的会话没有桌面端 owner，现有的审批卡片和 IPC 发送都接不上。所以想在桌面端开新对话就选 Codex，想直接开工就选 Codex CLI。
- Codex 桌面端队列（`thread-follower-set-queued-follow-ups-state`）：实现是用传入列表替换整个队列，读取接口和消息格式都未公开，写错会冲掉用户排好的内容。这也是不做排队的另一个原因。

## 技术骨架

```text
QuickInputPanel（NSPanel，nonactivating，可聚焦）
  └ QuickInputModel：draft、target、project、picker，Enter 和 ⌘Enter
       ├ QuickInputClient：六个对象和它们的深链
       ├ QuickInputSessionIndex：本机记录里猫条之外的会话
       ├ QuickInputCatalog：列表、排序，会话能否打开、能否发送
       ├ QuickInputLauncher / QuickInputRun：在默认终端里运行
       ├ QuickInputLiveness：进程还开着的会话
       └ state.sendAgentMessage：现有的 Codex IPC 发送
QuickInputController：窗口伸缩、飞行动画、回执窗口
```

- 用户文本走私有文件或 URL 编码，不拼 shell 字符串。
- 全局快捷键新增独立注册 ID，和现有 `InteractionShortcut` 的 ID 1、2 分开。
- 不保存任务全文。草稿只在内存里，启动时的提示词文件读取后即删。

`bash scripts/check-quick-input-e2e.sh <已信任的目录> [codexCLI claudeCode hermes] [--resume] [--open]` 用本机真实数据和默认终端真正启动 Agent，等它们的会话出现。会花少量额度，会话留着不关，不属于常规检查。

5. `claude://code/new` 是否带上目录和内容。

## 验收

- 未配置任何路由也能完整使用。
- 显式选择的目标不会被覆盖。
- 发送前能看清目标和动作，发送后回执与实际一致。
- 打开不会显示为已送达；发送后看到会话才写「交给 X 了」。
- 失败或结果不明时内容不丢，也不自动重发或改投。
- 关闭面板不影响已送达的任务，前台应用不变。
- 输入法组词时不会误发送。
- 能直接发的目标，Enter 发出后前台还回原应用；不能发的，内容跟到对方那里。面板里没有排队和打断。
- 选目标绝不会把内容发出去。
- 列表里的每个会话都能到，唯一例外是运行中且没有进程信息的会话，会明确提示。
- 提示词里的引号、`$()`、换行原样送达，不被执行。
- 开启「减少透明度」和「减弱动态效果」后，面板可读且动画退化。
